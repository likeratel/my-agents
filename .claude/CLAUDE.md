# 글로벌 지침

모든 프로젝트에 적용됩니다. 프로젝트에 `CLAUDE.md`나 `PROJECT_RULES.md`가 있으면 **그쪽이 우선**합니다.

코딩 규칙은 `~/.claude/rules/`에 있고 자동으로 읽힙니다. 여기서 반복하지 않습니다.

## 일의 구조

메인 세션이 **요구사항 해석·계획·판단**을 맡고, 손이 많이 가는 일을 서브에이전트에 내립니다.
요구사항을 해석하는 일은 절대 아래로 내리지 않습니다 — 여기서 틀리면 그 아래 작업이 전부 잘못된 전제 위에서
진행되고, 서브에이전트는 전제가 틀렸다는 걸 알 방법이 없습니다.

| 에이전트      | 모델   | 언제                                                  |
| ------------- | ------ | ----------------------------------------------------- |
| `scout`       | haiku  | 어디에 있는지 찾아야 하고, 검색이 여러 번 필요할 때    |
| `implementer` | sonnet | 무엇을 만들지 이미 정해진 뒤의 실제 구현              |
| `reviewer`    | opus   | 구현이 끝나고 커밋·다음 단계로 넘어가기 전            |
| `auditor`     | opus   | 인증·결제·개인정보를 건드렸거나 배포 전               |
| `scribe`      | haiku  | 코드 변경이 끝나고 문서를 맞춰야 할 때                |

## 서브에이전트를 쓰는 기준

**내리는 게 나을 때**

- 답을 얻기까지 파일을 여러 개 열어야 하는데 정작 필요한 건 결론뿐일 때 (컨텍스트가 실제로 절약됩니다)
- 서로 의존하지 않는 작업이 여럿이라 동시에 돌릴 수 있을 때
- 같은 코드를 다른 눈으로 한 번 더 봐야 할 때 (구현자가 자기 코드를 리뷰하면 놓칩니다)

**직접 하는 게 나을 때**

- 파일 하나를 읽으면 끝나는 일. 위임 왕복이 더 비쌉니다
- 이미 컨텍스트에 있는 내용
- 무엇을 원하는지 아직 확정되지 않은 일

## 위임할 때

지시를 **자족적으로** 씁니다. 서브에이전트는 이 대화를 보지 못합니다. 배경·범위·건드리면 안 되는 것·무엇을
돌려받고 싶은지를 지시 안에 다 넣습니다.

돌아온 결과를 그대로 믿지 않습니다. 특히 "다 됐다"는 보고는 근거를 확인합니다. 테스트가 통과했다고 하면
어떤 명령이 어떤 결과를 냈는지가 보고에 있어야 합니다.

## 웹 브라우징

gstack의 `/browse` 스킬을 씁니다. `mcp__claude-in-chrome__*` 도구는 쓰지 않습니다.

## 작업 성격별

여러 단계로 나뉘고 순서를 틀리면 되돌리기 어려운 작업(마이그레이션, 단계적 배포)은 `delivery-loop` 스킬을
따릅니다. 단발성 수정·버그 픽스에는 쓰지 않습니다 — 과합니다.
