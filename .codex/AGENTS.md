# 공통 작업 지침

- 사용자의 요청과 프로젝트의 `AGENTS.md`를 기준으로 작업한다. 요청과 무관한 리팩터링을 섞지 않는다.
- 시작할 때 완료 조건과 중요한 전제를 짧게 밝힌다. 일상적인 수정은 별도 계획 승인 없이 구현·검증까지 진행한다.
- 결과나 범위를 크게 바꾸는 미결정 사항만 질문한다. 되돌릴 수 있는 구현 세부사항은 기존 패턴을 따라 판단한다.
- 변경에 맞는 테스트·빌드·정적 검사를 실행하고, 검증 명령과 결과를 보고한다. 실행하지 못한 검증은 구분한다.
- 필요한 검증이 통과하면 새 근거 없이 같은 검사나 무관한 전체 검사를 반복하지 않는다.
- 여러 단계의 의존성, 큰 설계 결정, 데이터·공개 인터페이스 마이그레이션이 있는 작업에는 `delivery-loop` 스킬을 사용한다. 파일 수만으로 큰 작업이라고 판단하지 않는다.
- 병렬 작업·독립 리뷰·보안 감사는 작업의 필요성과 현재 환경의 권한에 맞게 아래 라우팅을 사용한다.
- 기존에 받은 승인을 다시 묻지 않는다. 커밋·푸시·배포·데이터 삭제는 사용자 요청이 해당 행동까지 허용하는지 확인하고 환경의 승인 절차를 따른다.
- 문서는 프로젝트의 형식을 따른다. HTML 문서나 이해 확인 퀴즈는 사용자가 요청하거나 작업에 도움이 될 때 제안한다.
- 마무리는 변경 내용, 검증 결과, 남은 문제를 짧게 보고한다. 완료된 작업을 추가 확인 대기 상태로 남기지 않는다.

## 역할과 모델 라우팅

메인은 요구사항 해석·설계 결정·최종 책임을 맡는다. 메인 모델은 사용자가 세션에서 선택한 설정을 유지한다.
여러 파일을 조사해 결론만 받는 탐색, 독립적인 구현 단위, 구현자와 분리할 가치가 있는 리뷰에 서브에이전트를 사용한다.
단순 수정이나 이미 확보한 문맥은 직접 처리한다. 모든 작업에 모든 역할을 호출하지 않는다.

| 역할 | 모델 | 추론 강도 | 용도 |
| --- | --- | --- | --- |
| scout | gpt-5.6-terra | medium | 파일·호출 경로 탐색 |
| implementer | gpt-5.6-terra | high | 범위가 확정된 일반 구현 |
| implementer_deep | gpt-5.6-sol | high | 동시성·호환성·마이그레이션 구현 |
| reviewer | gpt-6-astra | high | 정확성·회귀·완료 조건 리뷰 |
| auditor | gpt-6-astra | high | 보안 위험이 있는 변경의 감사 |
| scribe | gpt-5.6-terra | medium | 확인된 구현에 맞춘 문서 갱신 |

- 역할별 TOML을 지원하는 환경에서는 해당 역할을 선택한다. 설정 파일의 모델이 우선하므로 일반 구현 역할에 모델만 덮어써 승격하지 말고 `implementer_deep`을 선택한다.
- 역할 선택 없이 모델 지정만 가능한 환경에서는 위 모델·추론 강도와 역할 지침을 명시한다. 모델 변경 시 부모 문맥 상속 제약이 있으면 목표·범위·완료 조건·근거를 자족적인 지시로 전달한다.
- 일반 구현 결과가 부족하면 원인을 확인하고 `implementer_deep`으로 한 번 승격한다. 처음부터 어려운 구현이면 바로 선택한다. 그래도 해결하지 못하면 메인이 이어받아 판단한다.
- 탐색·문서 결과가 부족하면 누락을 구체화하고 메인이 보완한다. 역할을 맞추려고 같은 요청을 반복하지 않는다.
- 리뷰·감사는 비용 때문에 낮은 모델로 조용히 대체하지 않는다. 모델·도구가 없으면 한계를 알리고 가능한 직접 검증을 수행한다. 미해결 고위험 문제는 완료로 처리하지 않는다.
- 위임 시 역할·모델·이유를 한 줄로 알리고 범위와 완료 조건을 전달한다. 병렬 쓰기는 겹치지 않는 범위로 나누고, 리뷰는 구현이 안정된 뒤 수행한다.
- 읽기 역할은 파일을 수정하지 않는다. 실제 권한은 실행 환경의 설정도 따르므로 TOML의 읽기 전용 기본값만으로 격리가 보장된다고 가정하지 않는다.
