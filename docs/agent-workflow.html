에이전트 워크플로우

메인 오케스트레이션 · 모델 라우팅 · delivery-loop 자율 루프

my-agents 저장소 기준 · 파란 상자는 사람이 개입하는 지점

1. 구조 — 누가 누구에게 일을 내리나

메인 세션이 요구사항 해석·계획·라우팅을 맡고, 손이 가는 일을 다섯 서브에이전트에 내립니다. 요구사항 해석은 절대 아래로 내리지 않습니다.

2. 전체 경로 — 여러 단위로 나뉘는 작업

사람 게이트는 양끝에 모여 있습니다. 앞에서 무엇을 만들지 서명하고(B·C·D), 뒤에서 그대로 됐는지 검수합니다(E). 사이는 확정된 설계를 채점 기준 삼아 도는 자율 루프입니다.

자율 루프의 3원칙 · ① 앵커(확정된 설계)는 루프 안에서 고치지 않는다 ② 같은 단위 2회 상한 ③ 판정은 만든 손이 하지 않는다 — reviewer가 완료 조건을 항목별로 대조해 통과/불통과를 명시한다.

3. 경량 경로 — 한 번에 끝나는 작업

같은 원리를 계획 하나로 접습니다. 앵커가 설계 문서 대신 승인된 계획일 뿐입니다.

계획범위 · 완료 조건 · 영향 · 롤백. 모호하면 질문
→
계획 승인사람 서명 · 급소 있으면 퀴즈 1
→
자율 루프구현 → 리뷰·판정, 최대 2회
→
최종 확인사람 검수 · 퀴즈 0~2

예외는 오타 수정 · 한 줄 픽스 · 순수 질문뿐 — 그 외 모든 작업이 두 경로 중 하나를 탑니다.

4. 퀴즈 — 서명 게이트의 이해 검증

에이전트가 일하고 사람이 서명만 하면 이해가 침식됩니다(인지부채). 그래서 서명 직전에 서명하는 사람의 이해를 퀴즈로 확인합니다 — C 퀴즈(설계 3~5문항), E 최종 리뷰(구현 결과 2~3문항), 경량 경로의 승인(최대 1문항)·최종 확인(최대 2문항).

퀴즈는 시험이 아니라 거울입니다 · 급소만 냅니다 — 순서 제약의 이유, 롤백, 영향 범위, 무엇이 안 바뀌었나. 낼 급소가 없으면 내지 않습니다 · 객관식 2~4지선다, 오답 선택지는 그럴듯한 오해로 · 한 사이클 총 8문항 이하 · 오답은 블로킹이 아니라 신호 — 해설과 문서 위치를 제시하고, 문서가 불명확한 신호면 문서를 고칩니다.

5. 모델 라우팅 — 승격 사다리

작업의 모양으로 모델을 고릅니다. 결과가 불충분하면 한 단계 위로 1회만 승격하고, 강등은 없습니다. haiku는 쓰지 않습니다.
