# 큰 작업의 개발 루프

합의한 완료 조건을 기준으로 작업을 나누고, 구현과 검증을 끝까지 진행한다. 사용자의 기존 요청·승인과 프로젝트 규칙을 따른다.

## 설계와 완료 조건

현행 코드를 확인한 뒤 목표, 제외 범위, 중요한 전제, 단계별 완료 조건과 검증 방법을 정리한다.
순서가 중요하면 순서를 바꿀 때 깨지는 동작을 명시하고, 마이그레이션에는 호환성과 복구 방법을 포함한다.
문서가 필요한 규모면 프로젝트의 기존 문서 위치와 형식을 사용한다. 짧은 작업 계획은 대화에 남겨도 된다.

사용자 선택이 필요한 설계·범위·위험이 남아 있으면 해당 결정만 질문한다. 이미 합의된 설계는 다시 승인받지 않는다.
미결정 사항에 의존하지 않는 조사와 준비는 계속한다. 퀴즈나 HTML 산출물을 필수 단계로 만들지 않는다.

## 단계별 구현과 리뷰

1. 합의된 범위 안에서 한 단위를 구현하고 해당 완료 조건을 검증한다.
2. 결함·회귀·실패 경로와 완료 조건의 충족 여부를 리뷰한다. 독립 리뷰 도구나 서브에이전트가 허용되고 유용하면 구현자와 분리한다. 사용할 수 없으면 별도 리뷰 단계로 직접 확인하고 독립 리뷰를 받았다고 표현하지 않는다.
3. 발견한 문제를 수정하고 영향받은 검증을 다시 실행한다. 같은 단위의 리뷰 후 수정은 최대 두 차례로 제한한다. 그래도 완료 조건이 충족되지 않으면 근거·남은 문제·필요한 결정을 보고한다.
4. 통과한 단위는 변경과 검증 근거를 짧게 남기고 다음 단위로 진행한다. 매 단계 승인을 기다리지 않는다.

위임할 때는 목표, 수정 가능 범위, 완료 조건, 필요한 근거를 전달한다. 위임 결과의 실제 diff와 검증 결과를 확인한다.
보안 감사는 변경의 위험에 맞게 추가한다. 역할과 모델 선택은 적용 중인 `AGENTS.md`의 라우팅을 따른다.
라우팅이 없으면 현재 환경에서 가능한 도구와 역할을 사용한다.

## 계획과 현실이 다를 때

구현을 통과시키려고 완료 조건을 낮추거나 요구사항을 바꾸지 않는다.
완료 조건과 외부 동작을 유지하는 구현 세부사항은 자율적으로 조정하고 중요한 차이를 기록한다.
설계 결함이나 요청 밖의 영향이 발견되면 영향받는 단위를 멈추고 변경 이유와 선택지를 제시한다. 독립적인 작업은 계속할 수 있다.
커밋·푸시·배포·파괴적인 작업은 기존 승인 범위와 환경의 권한을 확인한다. 이 스킬 자체가 해당 행동을 승인하지 않는다.

## 마무리

전체 완료 조건을 대조하고 변경 내용, 실제 검증 결과, 설계와의 차이, 남은 위험을 보고한다.
프로젝트의 관련 정본 문서를 갱신한다. 사용자가 요청한 검수 절차가 없다면 추가 서명이나 퀴즈를 기다리지 않고 완료한다.
