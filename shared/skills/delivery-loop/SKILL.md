# 개발 변경 루프

합의한 완료 조건을 기준으로 작업을 규모에 맞게 나누고, 사용자 승인 뒤 구현·검증·독립 리뷰를 끝까지 진행한다. 사용자의 기존 요청·승인과 프로젝트 규칙을 따른다.

## 적용 시점과 우선순위

개발 변경을 위한 계획 요청부터 이 스킬을 먼저 읽고 적용한다. 구현 시작 시점까지 적용을 미루지 않는다. `plan` 등 계획 스킬은 이 흐름 안에서 계획 작성을 돕는 보조 수단이며 승인·구현·검증·독립 리뷰·최종 검수를 대체하지 않는다. 순수 질문과 읽기 전용 조사만 제외한다.

## 스킬·도구·플러그인 활용

이 스킬은 전체 작업 흐름과 완료 조건을 관리하며 각 단계의 실행 수단을 고정하지 않는다. OMX·gstack을 포함한 사용 가능한 스킬·도구·플러그인은 작업 적합성, 현재 환경의 기능과 권한을 기준으로 에이전트가 자율적으로 선택·조합한다. 예를 들어 계획에는 계획 스킬, 조사에는 검색 도구, 구현에는 역할별 에이전트, 검증에는 브라우저·테스트 도구나 QA 스킬을 활용할 수 있다. 예시는 필수 도구 목록이 아니다.

사용자가 지정한 수단과 적용 지침을 우선하고, 선택한 스킬의 지침을 읽어 해당 단계에 활용한다. 다른 워크플로가 만든 계획·구현·검증·리뷰 근거는 완료 조건에 맞는지 확인하여 재사용하며 같은 단계를 형식상 반복하지 않는다. 실행 수단을 선택하거나 바꾸는 것만으로 재승인을 요구하지 않는다.

위임하거나 다른 워크플로를 실행할 때도 기존 승인 범위, 계획·설계 변경 시 합의, 구현자와 분리된 독립 리뷰, 사용자 최종 검수 조건을 전달하고 유지한다. 도구의 자동 실행·완료 판정은 사용자 승인이나 최종 검수를 대신하지 않는다. 필요한 수단을 사용할 수 없으면 가능한 대안을 선택하고 검증·리뷰의 한계는 명시한다.

## 설계와 완료 조건

요청 이해, 목표, 제외 범위, 중요한 전제, 단계별 완료 조건과 검증 방법을 사용자에게 짧게 재진술한다. 불명확한 부분은 필요한 만큼 대화해 확인한다. 현행 코드는 승인 전에도 읽기 전용으로 확인할 수 있다.
순서가 중요하면 순서를 바꿀 때 깨지는 동작을 명시하고, 마이그레이션에는 호환성과 복구 방법을 포함한다.
문서가 필요한 규모면 프로젝트의 기존 문서 위치와 형식을 사용한다. 짧은 작업 계획은 대화에 남겨도 된다.

계획을 제시하고, 큰 설계 결정·데이터·공개 인터페이스 영향이 있으면 설계도 제시한다. 사용자의 명시적 동의가 있을 때 구현을 시작한다. 같은 범위의 기존 계획·설계 승인이나 사용자의 명시적 즉시 진행 지시가 있으면 재승인을 요구하지 않는다.
미결정 사항에 의존하지 않는 읽기 전용 조사와 준비는 계속한다. 실행 권한은 계획 승인을 대신하지 않는다. 퀴즈나 HTML 산출물을 필수 단계로 만들지 않는다.

## 단계별 구현과 리뷰

1. 합의·승인된 범위 안에서 한 단위를 구현하고 해당 완료 조건을 검증한다.
2. 구현자와 분리된 reviewer가 결함·회귀·실패 경로와 완료 조건의 충족 여부를 독립 리뷰한다. reviewer를 사용할 수 없으면 그 한계와 직접 수행한 검토를 공개하며, 독립 리뷰를 받았다고 표현하지 않는다.
3. 발견한 문제를 수정하고 영향받은 검증과 독립 리뷰를 다시 실행한다. 횟수를 고정하지 않되 같은 실패가 반복되거나 외부 블로커로 진행할 수 없으면 근거·남은 문제·가능한 결정을 보고하고 무한 반복하지 않는다.
4. 통과한 단위는 변경·검증·리뷰 근거를 짧게 남기고 다음 단위로 진행한다. 이미 승인된 범위에서는 단계마다 승인을 다시 기다리지 않는다.

위임할 때는 목표, 수정 가능 범위, 완료 조건, 필요한 근거와 메인이 받은 승인 범위를 전달한다. 하위 에이전트는 전달받은 승인 범위에서 구현하며 승인 대화를 다시 시작하지 않는다. 위임 결과의 실제 diff와 검증 결과를 확인한다.
scout은 탐색, implementer는 일반 구현, implementer_deep은 어려운 구현, reviewer는 독립 리뷰를 맡는다. 관련 보안 위험에는 auditor를 추가하고 문서가 필요하면 scribe를 사용한다. 역할별 모델·추론 강도·권한은 어댑터와 생성된 글로벌 라우팅을 참조하며, reviewer와 auditor의 구성된 모델을 비용 때문에 조용히 낮추지 않는다.

## 계획과 현실이 다를 때

구현을 통과시키려고 완료 조건을 낮추거나 요구사항을 바꾸지 않는다.
완료 조건과 외부 동작을 유지하는 구현 세부사항은 자율적으로 조정하고 중요한 차이를 기록한다.
설계 결함이나 요청 밖의 영향이 발견되면 영향받는 단위를 멈추고 변경 이유와 선택지를 제시한다. 독립적인 작업은 계속할 수 있다.
기존 승인 범위를 바꾸는 계획·설계 변경은 사용자가 명시적으로 동의한 뒤에만 영향받은 단위를 재개한다.
커밋·푸시·배포·파괴적인 작업은 기존 승인 범위와 환경의 권한을 확인한다. 이 스킬 자체가 해당 행동을 승인하지 않는다.

## 마무리

전체 완료 조건을 대조하고 변경 내용, 실제 검증·독립 리뷰 결과, 설계와의 차이, 남은 위험을 보고한다.
프로젝트의 관련 정본 문서를 갱신한다. 구현·검증 완료와 사용자 최종 검수는 구분하며, 사용자 검수를 자동 통과로 처리하지 않는다. 결과 보고로 현재 턴을 종료해 사용자 피드백을 받으며, 완료한 작업을 능동적으로 대기·sleep·poll하지 않는다. 퀴즈는 필수 단계가 아니다.
